The design decision we'd defend

The boundary isn't at signing. It's at reversibility.

Generate the wrong letter, convert it, merge it, hash it — redo any of it and nothing in the world has changed. A signature is different in kind: it is the agent making a legal assertion in a person's name, and there is no undo.

The agent owns this

Everything undoable

  • extract_data
  • generate_document
  • convert_document · merge_documents
  • hash_document
  • request_signature

Withheld, in code

apply_signature

  • needs a human confirmation
  • needs a single-use intent token
  • needs an unchanged document hash

The agent holds none of the three. Press Let the agent try to sign it in the demo and the API returns 403.

So an agent that gets confused, is prompt-injected by a malicious bill, or simply loops can waste tokens and write a bad letter. It cannot produce a signed one. We also hash before presenting, so the signer sees the hash of what they're about to sign — and an agent that alters the document in between invalidates its own envelope.
